# 初始架构

## 范围

先交付单用户 macOS 原生阅读器，接入本地 Magpie 或标准 RSS/Atom。
本地获取、解析、持久化与阅读不需要常驻业务服务器，也不启动 localhost HTTP 服务充当应用后端。
模型服务可由用户在本机、局域网或远程运行；应用只作为客户端连接。
第一版无需账号、云同步、推送服务、推荐广场或后台云任务。

## 语言与平台

Swift 承担 macOS 应用与可共享业务逻辑，SwiftUI 构建原生界面。
WebKit 渲染清理后的文章 HTML，AppKit 仅在 macOS 特有能力需要时使用。
SwiftUI 适合 Apple 多端；未来非 Apple 客户端单独实现 UI，不能把 SwiftUI 当作通用跨平台框架。
SQLite 是本地存储的初步候选，通过协议隔离，具体 Swift 封装在实现时评估。
最低系统版本在 App 工程建立时确定，不直接用本机系统版本作为产品最低要求。

## 目标模块边界（长期规划，非全部已创建）

| 模块 | 职责 | 依赖约束 |
| --- | --- | --- |
| ReaderDomain | Topic、Source、Article、订阅关系、阅读状态、模型配置引用 | 纯领域模型，不依赖 UI/网络实现/数据库 |
| ReaderApplication | 导入、刷新、读取、收藏、主题筛选、AI 用例与协议 | 依赖 Domain；通过协议调用基础设施 |
| FeedInfrastructure | RSS/Atom 获取与解析、OPML、抓取重试 | 实现 Feed 协议，不负责 UI 或模型推理 |
| ArticleProcessing | 全文提取、HTML 清理、URL 解析、结构保留 | 返回可渲染文档，不直接创建 WebView |
| LocalPersistence | 文章、Topic、关系、缓存、索引及迁移 | 实现存储协议，不提供隐含云同步 |
| ModelProviders | 本地/远程 API、流式输出、超时与错误映射 | 实现 AI 协议，不直接操作视图或订阅 |
| PlatformServices | Keychain、网络策略、设备内任务调度 | 平台适配，通过协议供应用层使用 |
| ReaderPresentation | 共享可复用状态和 SwiftUI 组件 | 调用应用用例，不绕过协议直接访问服务 |
| ArticleRenderer | WebKit 容器、打包的 CSS/字体/受限渲染器 | 只渲染经过清理的文档 |
| Apps/macOS | 窗口、菜单、快捷键、依赖组装 | 组合上述模块，持有平台入口 |

可以先在一个 Swift Package 中按 target 分界；只有实际复用或依赖需要时再拆成多个包。
采用构造注入和 Swift concurrency；不为初始化引入通用依赖注入框架。

## 数据流

```text
用户配置的订阅源（含本机 Magpie）
  → 设备内抓取与 XML 解析
  → 文章元数据与来源内容持久化
  → 刷新时预抓取正文 → 提取 → 清理 → 缓存并直接本地渲染

用户创建的 Topic
  → 关联来源与筛选偏好
  → 文章匹配、去重和排序
  → 精选 / 全部更新

用户触发 AI（或显式开启自动处理）
  → 限定上下文与目标模型
  → 设备直连用户 API
  → 单独保存生成结果及模型/内容版本
```

第一版 Topic 可先依赖手动关联与规则，不要求模型分类才能显示内容。
后续 AI 分类保留理由、版本和反馈；来源可靠性与单篇相关性独立建模。

## 原文阅读是第一条验收主线

保留 feed 原始内容与可取得的正文，清理结果不能覆盖来源快照。
不通过 AI 改写原文来修复排版。摘要订阅、全文抓取失败、付费内容截断应有明确状态。
图片与公式不可仅转成纯文本；保留代码空白、宽表格横向滚动、图片说明、脚注和引用链接。
远程图片由用户选择加载；无法获取时保留占位和替代文本。
从本地合成 fixture 验证：中文长文、英文技术博客、代码、表格、图片、公式、脚注、异常 HTML。
验收包括亮暗模式、缩放、窄屏、文本选择、复制代码、键盘操作与 VoiceOver。
未经许可不把抓取到的整篇第三方文章提交到公开仓库。

## 网络和隐私边界

没有本项目中转服务器，不代表离线或任何情形下内容不外发。
订阅刷新会向来源网站发请求；远程 AI 会收到选定上下文；用户选择加载的资源会向相应主机发请求。
记录请求的目的、目标与结果，日志不保存正文、认证头或含密钥的 URL。
允许用户明确配置本机/私网订阅和模型端点，区别于文章自动加载的链接。
重定向、外部资源、XML 外部实体和 WebView 导航不能获得这些配置端点的隐含权限。
密钥经 Keychain 获取并限制在目标 API 上使用；外部文章无法读取密钥或执行工具调用。
本地文件采用适当访问权限；数据库加密、备份和跨设备同步尚未实现，不宣传这些保障。

## 可解释的状态

- 来源：尚未刷新 / 更新中 / 成功 / 失败 / 待确认入口；显示最后成功时间。
- 文章：仅摘要 / 全文 / 提取失败 / 离线缓存；保留原文入口。
- AI：未配置 / 可用 / 能力未确认 / 处理中 / 失败；可以取消和重试。
- 配置测试：使用合成内容验证连接与必要能力，避免仅凭列出模型就宣称全部功能可用。
- 本地任务仅在系统允许执行时运行；应用退出或设备休眠后，下一次启动补拉。

## 建议实施顺序

1. 配置完整 Xcode，创建最小 macOS App 与核心 Swift Package。
2. 使用离线合成文章先做好阅读视图与排版验收。
3. 接入本地订阅获取、持久化、阅读状态和示例 Topic 导入。
4. 增加用户直连模型配置、连接测试、按需摘要/翻译/本文问答。
5. 增加主题匹配、去重、反馈，再评估来源发现与试订阅。
6. 验证 iOS/iPadOS 的共享边界，其他平台根据实际需求推进。

每一步单独可运行、可验证。

## 2026-11-09 Demo 实现状态

当前使用一个 Swift Package、四个实际业务 target：

- `ReaderDomain`：Topic/Source/Article/Library 与六来源 Demo 配置，不依赖 UI、数据库或模型供应商。
- `ReaderApplication`：Feed、正文提取、存储协议，应用服务与刷新合并规则。
- `ReaderAdapters`：FeedKit、SwiftSoup、JavaScriptCore/Readability、本地 JSON 存储、受限网络与本机代理配置。适配器按文件划分职责，暂未进一步拆包。
- `ReaderMac`：SwiftUI 展示状态、AppKit 窗口菜单、WebKit 阅读容器和依赖组装。

`ReaderChecks` 是离线验证可执行 target，在没有完整 Xcode 的环境下可运行。所有 fixture 均为合成内容。

正文提取使用随包附带的 Readability 0.6.0 和 JSDOMParser：SwiftSoup 先去掉脚本并规范化 HTML，JavaScriptCore 执行固定库，无网络/文件/原生桥，输出再次清理。WebKit 关闭页面脚本，CSP 阻止资源加载与连接。

当前界面只提供 LLM 一个 Topic；领域 Topic 用来源 ID 数组保留多对多扩展能力，但尚未实现多主题管理。来源可靠性评分、文章相关度评分、自动主题匹配、AI、调度和通用迁移仍属规划。

JSON 文件保存原始文章 HTML、清理后的阅读 HTML，以及用户触发提取时取得的原页面；未保存整个 feed XML。缓存不加密。手动刷新通过来源 URL 抓取，最多处理每源前 40 条；不启动本地 HTTP 服务。

Demo 的联网范围被限定为已配置来源主机；支持受限的本机代理，不等于允许文章链接访问私网。DNS 地址与跳转进行校验，但尚未实现连接层 IP 固定，不能宣称抵御所有 DNS rebinding。完整生产级网络审计仍需后续进行。

## 2026-11-10 全文预抓取

用户导入或刷新时，`ReaderApplication.ReaderService` 在获取订阅后合并旧缓存，自动调用正文提取协议。已有有效提取正文直接复用；新文章、旧摘要和失败条目逐篇获取页面并提取、清理。旧条目即使不在本次 feed 中，仍会补抓。每源新订阅解析上限仍为 40 条，已有缓存不受这个新条目上限影响。

macOS 界面并行处理六个来源，各来源内部顺序抓取，最多同时六个自动正文请求。通过异步回调逐篇发布结果，阅读区渲染完整的 `readingHTML`，列表仍使用短摘要。界面每处理十篇、每源完成及刷新结束时保存缓存；取消会保留已发布文章，未完成条目留待下次刷新。刷新与手动重抓互斥，避免重复请求和旧结果覆盖。

单篇提取失败不会中断来源刷新，保留订阅内容并显示提取错误；订阅获取失败则保留该源缓存并显示来源错误。成功提取后清除对应错误，但不能保证来源提供了完整文章（例如付费截断、动态页面）。原始订阅内容、原页面和清理正文分开保存，已有已读与收藏状态不变；继续使用现有 URL 校验、响应大小限制、HTML 清理及 WebKit 资源隔离，不加载原站活动页面。

启动仍只读本地缓存，不自动联网；用户按 ⌘R 即可为历史摘要补抓全文。CLI `--refresh-demo` 使用同一应用用例。无需模型、额外依赖或缓存格式迁移。
